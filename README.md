# Innova365 — Sistema de Gestión de Restaurantes

SaaS de gestión interna para restaurantes: pedidos, mesas, cocina, inventario, reportes y caja.

## Stack
- **Frontend**: React 18 + TypeScript + Vite + Tailwind CSS + React Query + Zustand
- **Backend**: Node.js + Express + TypeScript + Prisma + PostgreSQL
- **Auth**: JWT (access 15min) + Refresh Token (7d, httpOnly cookie)

---

## Requisitos previos
- Node.js 18+
- PostgreSQL 14+ corriendo en localhost:5432

---

## Configuración inicial

### 1. Base de datos
Crear la base de datos en PostgreSQL:
```sql
CREATE DATABASE restaurantos;
```

### 2. Backend

```bash
cd innova365/backend

# Editar .env con tu conexión PostgreSQL
# DATABASE_URL="postgresql://TU_USUARIO:TU_PASS@localhost:5432/restaurantos"

npm install

# Crear tablas
npx prisma migrate dev --name init

# Cargar datos de prueba
npm run db:seed
```

### 3. Frontend

```bash
cd innova365/frontend
npm install
```

## Flujo de pedido

```
PENDIENTE → EN_COCINA → EN_PREPARACION → LISTO → ENTREGADO → PAGADO
```

1. Mesero crea pedido → va directo a **EN_COCINA** (mesa pasa a OCUPADA)
2. Cocinero inicia → **EN_PREPARACION**
3. Cocinero termina → **LISTO**
4. Mesero entrega → **ENTREGADO** (inicia timer de mesa)
5. Caja cobra → **PAGADO** (mesa vuelve a LIBRE)

## Быстрый поиск

Поиск блюд и ингредиентов работает мгновенно (индекс в памяти браузера, без запросов к серверу): находит по части слова, с опечатками
(«кечуп»), при неверной раскладке («rehbwf» → «курица»), по нескольким словам и синонимам («картошка» → «картофель»).
Глобальный поиск — **Ctrl+K** на любой странице; **/** — фокус на поле поиска. Движок: `frontend/src/search/engine.ts`.

## Склад и закупки

Раздел **Склад** (только администратор/владелец): Остатки · Закупки · Поставщики · Движение · Ревизия.

* Закупка у поставщика → **приёмка**: для каждой позиции указывается, сколько реально привезли (`0` = не привезли). Можно принять частично и
  дождаться следующей поставки либо закрыть закупку с недопоставкой.
* Каждое изменение остатка — запись в журнале движений (кто, когда, сколько, остаток после). Остаток нельзя править «молча»: только
  закупкой, корректировкой/списанием или ревизией (пересчётом).
* Операции идемпотентны: повтор запроса (плохая сеть, двойной тап) не удваивает остатки.
* Скорость: приёмка — одна транзакция и один HTTP-запрос (~30–60 мс на сервере, ответ < 1 КБ), интерфейс обновляется мгновенно (оптимистично).

## Печать

**Настройки → Принтеры.** Поддерживается:

| Тип | Как подключить |
|---|---|
| Сеть (LAN/Wi-Fi) | Кассовый принтер с IP-адресом, порт 9100 — сервер печатает напрямую (ESC/POS) |
| USB / Windows | Агент печати на ПК с принтером — см. [`print-agent/README.md`](print-agent/README.md) |
| Браузер | Обычное окно печати: офисные принтеры A4 (отчёты, ревизия, закупки) |

Документы: чек, предварительный счёт, тикет на кухню, итоги дня (термопринтер); отчёт о продажах, заказ поставщику, лист ревизии,
остатки и журнал движений (A4). Печать автоматическая (кухня при создании заказа, чек при оплате) включается галочкой у принтера.
Если принтер недоступен — открывается печать через браузер, чек не теряется.

**Сетевой принтер (Ethernet в роутер).** *Настройки → Принтеры → «Найти в сети»*: приложение определяет вашу подсеть, сканирует её на порт 9100,
показывает найденные принтеры со статусом (в сети, бумага) и подключает в один клик; есть проверка конкретного IP и пошаговая инструкция,
если принтер не виден (самотест с IP, смена заводского IP на адрес вашей сети).

**Формат чека.** Рулонная лента 58 / 80 / 90 мм (ширина задаётся у принтера), таблица позиций «Наименование · Кол · Цена · Сумма»
и QR-код под итогом. Содержимое QR — **Настройки → Общие → «Содержимое QR»**: можно указать ссылку с подстановками
`{numero} {total} {fecha} {id} {restaurante}` (например, страницу отзыва), по умолчанию — строка с данными чека. Отчёты, ревизия и закупки
всегда печатаются на **A4**. Печать через браузер сама подбирает высоту ленты по длине чека
(Chrome/Edge не понимают `size: auto` и иначе печатают на листе).

## Часовой пояс

Переменная `TZ` в `.env` (по умолчанию `Asia/Almaty`) задаёт время на чеках и границы «сегодня» в отчётах.


## Печать: окно печати, умный выбор принтера, размеры

* Любая печать (чек, счёт, отчёты A4, закупки, ревизия) открывает **собственное окно печати Innova365**: предпросмотр, выбор принтера, бумага 58/80/90 мм или A4.
* **Авто (умный выбор):** сервер проверяет принтеры (онлайн/офлайн, бумага, отклик) и берёт живой и самый быстрый; если он не ответил — сразу следующий (failover), затем окно браузера. Состояние видно цветными точками.
* **Размеры:** рулон — ширина ленты, высота считается по содержимому; не помещается — шрифт уменьшается (до 8 px), затем масштаб. A4 — если таблица шире листа, масштаб «по ширине» или автоматически альбомная ориентация.
* **Печатать сразу** (галочка в окне) — чеки уходят на выбранный принтер без показа окна.
* USB: агент печати (`print-agent/install-agent.bat`), имя принтера `auto`. Сеть: IP принтера, порт 9100 («Настройки → Принтеры → Найти в сети»).
* Печать через браузер без системного диалога: `print-agent/start-pos-browser.bat`.
